# 2026-09-08 · 第3题 · 亲密数对(Amicable Pairs)

- 主题: 循环与嵌套循环
- 难度: 中等

## 📝 题目

### 题目描述

古希腊数学家发现: 220 的所有真因数(能整除它且不等于它自身的正因数)之和为 `1+2+4+5+10+11+20+22+44+55+110 = 284`, 而 284 的真因数之和又正好是 220。这样一对互相"等于对方真因数和"的数叫**亲密数对**。

请找出 `[1, n]` 范围内所有亲密数对 `(a, b)`, 要求 `a < b`。

注意区分:**完全数**(如 6、28、496)的真因数和等于自身, 它不构成亲密数对, 不要输出。

### 输入 / 输出约定

- 函数签名: `def find_amicable(n: int) -> list[tuple[int, int]]`, 返回按 a 升序排列的亲密数对列表
- 主程序: 从标准输入读一行整数 n → 每对一行输出 `a b`(空格分隔); 若无任何亲密数对, 输出零行(什么都不打印)
- 约束: `2 ≤ n ≤ 100000`, 全整数运算

### 样例

```
find_amicable(2)    -> []                        # 范围太小, 最小一对是 (220, 284)
find_amicable(284)  -> [(220, 284)]              # 恰好包含第一对的上界
find_amicable(1000) -> [(220, 284)]              # 陷阱: 6/28/496 是完全数, 不能凑成对
find_amicable(3000) -> [(220, 284), (1184, 1210), (2620, 2924)]
```

```
stdin: 1000
stdout:
220 284
```

### 实现要求

- 主题考点是**嵌套循环**: 建议先一次性预计算 `1..n` 每个数的真因数和(倍数标记法: 外层 i 从 1 到 n, 内层 j 从 2i 起步每次 += i 累加), 再单层扫描配对; 别在配对时对每个数重复枚举因数
- 边界: 完全数剔除靠 `a < b` 与对称条件自然拦掉, 别另写魔法数特判; `b` 超出 n 范围的候选直接跳过
- n = 100000 时程序须在 2 秒内跑完; 禁止第三方库
- `find_amicable` 纯函数可独立测试 + `if __name__ == "__main__":` 主入口

## 💻 我的代码

见 `solutions/2026-09-08.py`(参考实现版)。核心两段:

```python
s = [0] * (n + 1)
for i in range(1, n // 2 + 1):      # 倍数标记法预计算真因数和
    for j in range(2 * i, n + 1, i):
        s[j] += i

for a in range(1, n + 1):           # 单层扫描配对
    b = s[a]
    if a < b <= n and s[b] == a:
        pairs.append((a, b))
```

## 🧪 运行结果与验收

- 4 个样例全部通过: `find_amicable(2) == []`、`(284) == [(220,284)]`、`(1000) == [(220,284)]`(6/28/496 被正确剔除)、`(3000)` 恰好 3 对
- 性能: `n = 100000` 找出全部 **13 对**, 耗时 **0.067s**(限制 2s)
- 主程序: `echo 1000 | python3 solutions/2026-09-08.py` 输出 `220 284` ✅

## 💡 改进意见

- 倍数标记法(类埃氏筛)把"每个数枚举因数"的 O(n²) 降为 O(n log n): 外层因数 i、内层倍数 j 从 `2i` 起步(排除自身, 天然是"真"因数); i 只需到 `n//2`
- 配对条件 `a < b <= n and s[b] == a` 一个表达式同时完成: 排除完全数、去重、保证 b 的真因数和已预计算
- 用定长列表 `s[x]` 按下标直查, 不要用 append 导致下标与数值错位

## ⚠️ 当前问题 / 复盘

首版代码的教训(已修复):

1. **内层循环变量 `n` 覆盖了函数参数 `n`** —— 最致命的 bug, 循环变量务必另起名
2. 只有真因数求和, 完全没有配对逻辑, 且 `return` 空语句返回了 `None`
3. `sum_list` 从 3 开始 append, 下标与数值对不上, 无法 O(1) 查询 `s(b)`
4. O(n²) 枚举因数, `n=100000` 约 5×10⁹ 次取余, 必然超时 —— 算法选型问题, 小修小补救不回来
