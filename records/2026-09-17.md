- 主题: 函数与参数
- 难度: 中等

## 📝 题目

### 题目描述

写一个通用的接口地址构造器 `build_query`，把 base 地址、若干路径片段和各种"可选参数"拼成一条完整的请求地址。

难点全在**函数参数本身**：位置参数、可变位置参数 `*paths`、默认参数、仅关键字参数、可变关键字参数 `**kwargs` 的合并与覆盖顺序，以及"不许污染调用方传进来的字典"。

### 输入 / 输出约定

函数签名固定为：

```python
def build_query(base, *paths, params=None, sort_params=True, drop_none=True, **kwargs):
    ...
```

规则：

1. **base**：去掉末尾的 `/`（只去末尾，协议里的 `//` 不动）。
2. **paths**：`*paths` 里的每一项先 `strip("/")`；`strip` 后为空串或本身就是 `None` 的，忽略。剩下的按原顺序用 `/` 连接拼到 base 后面；一个都没剩就只用 base。
3. **参数合并**：先取 `params`（字典，默认 `None` 当空字典），再用 `kwargs` 覆盖同名键（`kwargs` 优先级高）。输出顺序：`params` 中原有的键保持原插入顺序，`kwargs` 新增的键按传入顺序追加在后面。
4. **drop_none**：为 `True` 时丢弃值为 `None` 的项；为 `False` 时保留，并输出成 `key=`（等号右边为空）。
5. **sort_params**：为 `True` 时按 key 的字典序（Python 默认字符串比较）升序排序；为 `False` 时保持第 3 步的顺序。
6. **转义**：键和值都先 `str()`，再用 `urllib.parse.quote(..., safe="")` 转义（路径部分不转义）。
7. 最终没有有效参数时不加 `?`；有参数则 `?` 后接 `key=value`，用 `&` 连接。
8. **不得修改调用方传入的 `params` 字典**（不许原地 pop / 写入）。
9. 允许 `from urllib.parse import quote`，其余只用内置函数。

### 样例

```python
>>> build_query("https://api.example.com/", "v1", "users")
'https://api.example.com/v1/users'

>>> build_query("https://api.example.com", "v1/users/", None, "", "detail",
...             page_size=20, page=2)
'https://api.example.com/v1/users/detail?page=2&page_size=20'

>>> build_query("https://api.example.com", "search",
...             params={"q": "hello world", "lang": None, "page": 1},
...             q="python 3.13", limit=5)
'https://api.example.com/search?limit=5&page=1&q=python%203.13'

>>> p = {"b": 1, "a": None}
>>> build_query("https://api.example.com", params=p,
...             sort_params=False, drop_none=False, c=2)
'https://api.example.com?b=1&a=&c=2'
>>> p
{'b': 1, 'a': None}          # 原字典没被改
```

- 注意 `None`、空串、`bool` 值（`True` 输出 `True`）这些边界；`paths` 数量不限。
